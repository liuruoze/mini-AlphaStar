# 评测协议 v3（多选，2026-11-20 19:35 定稿）

> 相对 v2 的根本改动：**从「五选一」改为「五位独立判断」**。
> 理由（用户）：造农民在基地排队、造兵在兵营排队、造建筑由农民执行，三者互不冲突，可以同时进行。
> v2（单选）与 v3 不可比；v3 起以本文件为准。

## 1. System（逐字使用）

```
你是星际争霸2神族的战术指挥官。本局固定执行狂热者快攻。以下五件事要分别判断“现在是否该做”，可以同时为真：

1. 补水晶：没有水晶，或（人口余量（上限−已用）≤ 9 且人口上限未满 200）
2. 补农民：农民 ≤ 14 且人口余量 ≥ 1
3. 补兵营：兵营 < 3 且至少有一个水晶（没有能量场就放不下）
4. 量产狂热者：兵 < 24 且矿 ≥ 100 且农民 ≥ 10 且兵营 ≥ 1 且人口余量 ≥ 2
5. 全面进攻：兵 ≥ 8

按 1..5 的顺序输出 5 位 0/1（1 = 现在该做），不要解释。
```

## 2. User 模板（逐字使用）

```
时间 {mm:ss}｜人口 {used}/{cap}（余量 {gap}）
矿 {minerals} 气 0｜农民 {workers}
部队构成：{兵种×数量，降序，无则"无"}
建筑：{基地×n、水晶×n、兵营×n}

输出（5 位 0/1）：
```

**不再出现的字段**：空闲农民（没有任何规则使用它，属纯干扰项，19:33 删除）、敌方信息（未采集）、历史决策（避免路径依赖）。

## 3. 输出格式与依赖

5 位 0/1，可含多个 1。例：`00110` = 补兵营 + 量产狂热者。

唯一的位置依赖：没有水晶 → 第 3 位强制 0（能量场不存在，兵营放不下）。
其余四位相互独立；补水晶与补兵营可同时为 1（两个农民分别去建）。

## 4. 指标

| 指标 | 定义 | 说明 |
|---|---|---|
| **平衡准确率 A** | 每位分别算 (TPR+TNR)/2，再对五位平均 | **主指标**。只答一边恒为 50%，不受分布偏斜影响 |
| 逐位准确率 A_raw | 答对的位数 /（5 × 题数） | 参考值，会随分布偏斜虚高（见下） |
| 全对率 E | 5 位全对的题数 / 题数 | 次要 |
| 格式失败 F | 输出不是合法 5 位 0/1 的题数 | 单列，不计入 A |

**为什么用平衡准确率**：实测若按逐位准确率，一个"什么都不做"的模型能拿 **58.5%**（因为每位为 1 的占比只有 42–60%），
而平衡准确率下它恰好是 **50.0%**。这样 80% 的门槛才有意义。

门禁：8 局并发下 p95 延迟 ≤ 30 秒（不过门禁不参与排名）。
判定：A ≥ 0.8 可进在线测试；0.6–0.8 仅离线；< 0.6 淘汰。

- 时间：农民 ≤ 12+t/12、兵营 ≤ 1+t/45、兵 ≤ (t/27)×（当前或曾可能有的兵营数）；

- 单位范围：**只含狂热者体系**（农民/狂热者/基地/水晶/兵营）；
- 合法特例：兵营为 0 但仍有狂热者（兵营被拆光，老兵还在），约占 12%。
