## 1. System（原文，逐字使用）

```
你是星际争霸2神族的战术指挥官。本局固定执行狂热者快攻，你的唯一职责是节奏控制。

注意：兵营必须建在水晶的能量场里，所以没有任何水晶时，一切其他建造都无从谈起。

1. 水晶 = 0 → 补水晶
2. 人口余量（上限−已用）≤ 9 → 补水晶
3. 农民 ≤ 14 → 补农民
4. 兵营 < 3 → 补兵营
5. 兵 ≥ 8 → 全面进攻
6. 其余 → 量产狂热者

只输出一个 5 位编码（由 0 和 1 组成），不要解释。
```

## 2. 编码表（one-hot，用户指定）

| 决策 | 编码 |
|---|---|
| 补水晶 | `00001` |
| 补农民 | `00010` |
| 补兵营 | `00100` |
| 量产狂热者 | `01000` |

选择理由：数字/字母编号带有顺序先验（实测模型有"选第一个"倾向），one-hot 无语义顺序。

## 4. 解析规则

1. 先剥掉思考模型的 ` thinking...<｜end▁of▁thinking｜>` 块（取最后一个结束标记之后的内容）；
2. 去掉空白与标点，取**第一个**长度 5、仅含 0/1 的串；
3. 该串不在编码表中 → 记为**格式失败**（单独统计，不计入答错）；
4. 合法但与原答案不同 → 计**答错**。

## 8. 与 33 条人工标注的关系（重要）

那 33 条标注支持的是 **v1**（进攻 = 7:00 且兵≥10、含"再补一个兵营"规则）。
**v2 是用户主动修改后的战术**：删了第 4 条、进攻改成兵≥8 且无时间门、加了"水晶=0"前置。

因此：

- v1 在 33 条上 33/33；
- **v2 与那 33 条不再一致**，不能再用"人工标注一致率"证明 v2 的正确性；
- 若论文需要"人类标准"，必须重新标注一批 v2 下的边界局面（约 15–20 条即可）。
